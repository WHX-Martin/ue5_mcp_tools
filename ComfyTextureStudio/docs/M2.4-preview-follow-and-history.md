# M2.4 报告 · 右栏预览不跟随新产物 + 「历史候选」从未渲染

| 项 | 值 |
|---|---|
| 日期 | 2026-10-14 |
| 触发 | 用户报：「如果有生成的贴图，在新生成贴图后，新的贴图不会在右边的预览栏显示，仍是旧的图片，而且预览下方的历史也没有」 |
| 引擎 | UE 5.8.3（`++UE5+Release-5.8-CL-58210709`），`-NoUBA` |
| 结论 | 两条独立缺陷 + 一并堵住一处"UI 显示 A、实际用 B"的静默错配；四层验证全绿 |

一句话概括：**预览区的状态迁移写成了"只在空时赋值"，而历史候选从头到尾没有被渲染过。**
两条都不报错、UI 上都看不出异常（图有、缩略图也有，只是那张图是旧的）。

---

## 1. 现场

用户这次会话（`Saved/Logs/ComfyTextureStudioHost-backup-2026.10.14-15.18.17.log`）跑了 5 次：

| 时刻 | 任务 | 类型 |
|---|---|---|
| 23:08:38 | `20261014-230838_2D32FF` | 只跑阶段A |
| 23:09:07 | `20261014-230907_80C02D` | 只跑阶段A |
| 23:09:25 | `20261014-230925_AD577D` | 阶段A + B |
| 23:13:39 | `20261014-231339_F67C88` | 只跑阶段A（换种子重出） |
| 23:13:57 | `20261014-231357_322C50` | 阶段A + B |

第 2 次起（`230907`）预览就已经不再更新了 —— 停在 `230838` 那张；之后 `231339` 那次"换种子重出"
跑出新图后，右栏仍是 `230925` 的 albedo。「历史候选」区从头到尾只有孤零零一个 `#1`。

## 2. 三处根因

### 2.1 预览只在「焦点为空」时才更新（★ 主因）

`SComfyTextureStudioPanel::OnActiveTimer`：

```cpp
// 旧实现
if (Job->IsAwaitingStageAReview() && !LastResult.BaseTexturePath.IsEmpty())
{
    if (!StageAHistory.Contains(LastResult.BaseTexturePath)) { ...插入历史... }

    if (FocusedPreviewPath.IsEmpty())          // ← 只有第一次出产物时为真
    {
        FocusedPreviewPath = LastResult.BaseTexturePath;
    }
}
```

这个条件在第一次有产物时成立、之后**永远为假**。文件是新的、`PreviewCache` 里也有新条目，
只是「当前该显示哪张」这个变量没被改过。

**为什么它极难发现**：把这条判断删掉，UI 表现和正确实现**一模一样** ——
有图、有 2×2 平铺、有缩略图。唯一的差别是那张图是上一轮的。没有断言就只能靠"盯着看觉得不对"。

### 2.2 2×2 平铺预览在构造期把空路径固化进了 4 个槽位

```cpp
// 旧实现：BuildPreviewColumn() 里
BuildTiledPreview(FocusedPreviewPath, 75.0f)
// 而 BuildTiledPreview 内部
SNew(SImage).Image_Lambda([this, PngPath]() { return GetPreviewBrush(PngPath); })  // ← 按值捕获
```

`BuildPreviewColumn()` 只在 `Construct()` 里跑一次，那时 `FocusedPreviewPath` 还是空串 ——
于是平铺区从建起来那一刻就绑死在空路径上，**再也不可能显示任何东西**。
（这一条与 2.1 是独立的：即使焦点更新了，平铺区也还是空白。）

现在的写法是不接收路径参数，lambda 只捕获 `this`、每帧读成员。
属性绑定每帧重算，路径一变就跟着变。

### 2.3 「历史候选」是写死的单槽 —— 数据有，UI 没有

`StageAHistory`（最多 8 项、最新在前）**从 M2 起就一直在正确维护**，但 UI 是手工搭的一个槽：

```cpp
// 旧实现：一个固定槽，标签写死 "#1"，显示的内容就是当前焦点那张
SNew(SBox).WidthOverride(48.0f).HeightOverride(48.0f)
[
    SNew(SImage).Image_Lambda([this]() { return GetPreviewBrush(FocusedPreviewPath); })
]
+ ... MakeNote(LOCTEXT("Candidate", "#1"))
```

也就是说：用户看到的"历史"其实就是右栏那张图的缩小版，**真正的历史从来没被渲染过**。
PRD §7.2 的草图（第 700~711 行）里画着 `#1 #2 #3 #4`，实现从未与它对齐。

> 这类缺陷的检查表应该问一句：**"这份数据现在有谁在显示它？"**
> 数据类型有了、写入点有了、测试也过了，唯独自呈现层那条线断了 —— 而且没有任何报错。

## 3. 顺带堵住的一处静默错配：阶段B 吃的不一定是用户看到的那张

加历史候选的**点选**能力就绕不开这个问题：

`FComfyTextureJob::Step_UploadInput()` 原先固定用 `Result.BaseTexturePath`
（本次阶段A 的产物）。而用户完全可以点历史候选里的第 2 张、然后按「✓ 用这张继续」——
那就成了「UI 显示 A、实际拿 B 去跑几何反演」。产出的 PBR 与看到的对不上，
**面板上没有任何东西会因此变色**。

改法：

- `ContinueToStageB(const FString& OverrideInputPath = FString())`，默认参数保证既有调用点行为不变。
- 判定集中在 `FStageAHistory::ResolveStageBInput()`，三条规则都要成立才覆盖：
  1. 焦点非空；
  2. 焦点**确实在历史候选里**（否则可能是阶段B 的产物 albedo）；
  3. 焦点与本次产物不同。

第 2 条是负向保护：阶段B 跑完后焦点会落到 albedo，若不加这条，再点一次「生成 PBR 全套」
就会拿 albedo 当输入二次反演 —— 而且是静默的。回归用例 ④ 钉住了它。

## 4. 修复清单

**新增（Runtime 模块）**

- `ComfyPreviewFocus.h/.cpp` —— `ComfyPreview::FStageAHistory`：历史候选（去重/封顶/最新在前）
  + 焦点（跟随 / 钉住 / 解除钉住）+ `ResolveStageBInput`。
  **不依赖 Slate**，所以能在 commandlet 里跑负向回归；原来的实现藏在 widget 的匿名命名空间里，
  既不能单测也不能回归 —— 与 M2.3 的提示词骨架是同一个教训。

**修改**

- `SComfyTextureStudioPanel.h/.cpp`
  - 右栏三处绑定改为每帧读 `PreviewHistory`（不再传参、不再按值捕获）。
  - 「历史候选」改为渲染真实列表：横向滚动、每项 48×48、单击切换焦点、
    当前项标 `✓当前`（用文字而不是边框：不去猜引擎里哪个 brush 名可靠，
    也不给贴图叠色偏 —— 判色时色偏是有害的）、空态给一句提示、标题显示数量。
  - 大图下方那行改成动态的「当前预览：xxx.png · 阶段A 候选 #N / 阶段B 产物」，
    免得切到 albedo 之后还写着"原图"。
  - 「丢弃」不再清历史：那张图在磁盘上还在（`stage_a/` 不删），清掉只是让用户找不回来。
  - 新增 `TrimPreviewCache()`：缓存超过 24 项时淘汰最旧的，但**只淘汰文件仍在磁盘上的**——
    导入后 `stage_b` 的中转 PNG 会被删（`PreserveDownloadedPng=false`），
    那些条目一旦淘汰就再也加载不回来，缩略图会变空白（M2.3 修过的那类故障换个入口重现）。
- `ComfyTextureJob.h/.cpp` —— `ContinueToStageB(OverrideInputPath)` + `GetStageBInputPath()`，
  并在提交时把实际喂进去的图打进日志。
- `ComfyTextureStudioCommandlet.cpp` —— 新增 `-TestPreviewFocus`（17 条断言）。
- `PRD.md` §7.2.2、`README.md`。

## 6. 教训

1. **`if (X.IsEmpty()) X = 新值;` 是最危险的一类状态迁移。** 正确实现与错误实现
   在 UI 上完全同形（都有图），只有"图是旧的"这一条软信号。凡是"只在空时赋值"的字段，
   都要问：**非空以后，它还会被更新吗？**
2. **文档画了、数据类型也有了，不等于接上了。** 检查表要多问一句
   "这份数据现在有谁在显示它？"—— 数据与呈现之间那条线断了是没有任何报错的。
3. **构造期按值捕获成员是 Slate 的经典坑。** `BuildTiledPreview(FocusedPreviewPath, 75)`
   把"当时的值"固化进了控件。凡是绑定到会变的量，一律 lambda 读成员，不要传参。
4. **同一份数据的两个入口必须给同一份答案。** 右栏显示哪张，阶段B 就该吃哪张 ——
   "UI 显示 A、实际用 B"比崩溃更难发现，而且产出物看起来"正常"，只是对不上。
5. **缓存淘汰先问"这条能不能重建"。** 中转 PNG 导入后被删，缓存淘汰一次就永久丢失。
   淘汰策略要区分"可重建"与"不可重建"，后者宁可占内存。
