# M2.1 · SamplerType 编译失败修复

> 起因：M2 交付的材质在编辑器里打开后编译不过，材质缩略图上两行红字。
> 这是 M2 的**验收漏项**，不是新需求 —— 所以单独立一个补丁报告。

## 1. 症状

在编辑器里打开 `/Game/ComfyTextures/cts_m2_verify2/M_cts_m2_verify2`：

```
SM5 (Node TextureSampleParameter2D) Sampler type is Grayscale,
    should be Linear Grayscale for /Game/ComfyTextures/cts_m2_verify2/T_cts_m2_verify2_H.T_cts_m2_verify2_H
SM5 (Node TextureSampleParameter2D) Sampler type is Linear Color,
    should be Masks for /Game/ComfyTextures/cts_m2_verify2/T_cts_m2_verify2_ORM.T_cts_m2_verify2_ORM
```

对照 M2 的验收报告 —— 它写的是「材质编译 **0 错误**」。

**同一份产物，两套结论。** 这说明 M2 的验收里有一条腿是瘸的，比错误本身更值得查。

## 2. 三条根因（一条比一条深）

### 2.1 规范写错了，代码忠实实现了错规范

`docs/PRD.md` §6.2 原文：

> | SamplerType | albedo→`SAMPLERTYPE_Color`；**ORM→`SAMPLERTYPE_LinearColor`**；
> **normal→`SAMPLERTYPE_Normal`**；**height→`SAMPLERTYPE_Grayscale`** |

`ComfyMaterialBuilder.cpp` 就是照这张表硬编码的（第 273/275/277/286 行）。
四条里**错了两条**：

| 贴图 | 压缩格式 | PRD 写的 | 引擎要的 | |
|---|---|---|---|---|
| albedo | `TC_Default` + sRGB | `Color` | `Color` | ✅ |
| normal | `TC_Normalmap` | `Normal` | `Normal` | ✅ |
| **orm** | `TC_Masks` | `LinearColor` | **`Masks`** | ❌ |
| **height** | `TC_Grayscale`, sRGB off | `Grayscale` | **`LinearGrayscale`** | ❌ |

引擎的推导规则在 `MaterialExpressionUtils::GetSamplerTypeForTexture()`：

```cpp
case TC_Grayscale:
    return Texture->SRGB ? SAMPLERTYPE_Grayscale : SAMPLERTYPE_LinearGrayscale;
case TC_Masks:
    return SAMPLERTYPE_Masks;
```

关键点：**`Grayscale` 是 sRGB 版本**（会把灰度值做 sRGB→Linear 解码），而我们的 height
是 `sRGB=false` 的线性数据，所以必须是 `LinearGrayscale`。这条规则不手写、直接问引擎，
就不会错。

### 2.2 自检压根没查这一项

M2 的属性表自检（`ImportOne`）查的是**贴图侧** 6 个属性：`CompressionSettings` / `sRGB` /
`FlipGreenChannel` / `LODGroup` / `AddressX` / `AddressY`。
冷加载核对（`VerifyImportedAssets`）查的是贴图属性 + 材质图的**连线结构**。

两边都没有检查「材质节点 ↔ 贴图」之间的这层一致性。**没被定义的检查项，就一定会漏。**

### 2.3 "编译 0 错误"是假绿灯（最危险的一条）

`UMaterialEditingLibrary::RecompileMaterial` 的实现（引擎 `MaterialEditingLibrary.cpp:1054`）：

```cpp
if (const FMaterialResource* Resource = Material->GetMaterialResource(GMaxRHIShaderPlatform))
{
    return Resource->GetCompileErrors();
}
return {};      // ← 拿不到资源就返回**空数组**
```

无头 commandlet 下 `GetMaterialResource()` 返回 null ⇒ 它返回 `{}` ⇒ 调用方看到"0 错误"。
**编译根本没跑。**

M2 的代码把 `bCompiledClean = (CompileErrors.Num() == 0)` 当作"编译通过"，
于是把"没编"记录成了"编过了"。这条假绿灯让 2.1 + 2.2 的漏洞一路通过验收。

## 3. 修复

### 3.1 单一权威来源：`ComfySamplerType`（新文件，Runtime 模块）

```
Source/ComfyTextureStudio/Public/ComfySamplerType.h
Source/ComfyTextureStudio/Private/ComfySamplerType.cpp
```

只做三件事，且**不维护自己的映射表**：

| 函数 | 作用 |
|---|---|
| `ForTexture(UTexture*)` | 转发 `MaterialExpressionUtils::GetSamplerTypeForTexture()` |
| `Verify(UTexture*, Actual, OutError)` | 转发 `MaterialExpressionUtils::VerifySamplerType()` |
| `DisplayName(EMaterialSamplerType)` | 枚举显示名（"Masks" / "Linear Grayscale"） |

放在 Runtime 模块（只依赖 Engine），让**建材质**（Editor）、**冷加载核对**（Editor）、
**回归测试**（commandlet / Runtime）三处共用同一份实现。

> 为什么用引擎的 `VerifySamplerType` 而不是自己写 `if (Actual != Expected)`：
> 错误文案与编辑器里那条红字**同源**，用户拿我们的报告去比对报错时不会出现"两套说法"。
> 附带好处：引擎将来加规则（比如虚拟纹理的平台回退、`HasRuntimeVariableSRGB` 的宽容）
> 我们自动跟上。

### 3.2 建材质：不再由调用方指定 SamplerType

`MakeTextureSample()` 去掉 `SamplerType` 入参：

```cpp
Sample->Texture = Texture;
Sample->SamplerType = ComfySamplerType::ForTexture(Texture);   // 由贴图推导，调用方说了不算
```

新增 `VerifySamplerTypes()`：建完立刻对**所有**采样节点回读断言（不只接了线的那些），
不符就进 `SamplerTypeMismatches` 并让 `Build()` 返回 false。

### 3.3 把"编过了"和"没编"分开

新增字段 `FComfyMaterialBuildEntry::bCompileResultValid`：

```cpp
OutEntry.bCompileResultValid = (Material->GetMaterialResource(GMaxRHIShaderPlatform) != nullptr);
```

报告里的措辞随之改变：

| 情形 | 报告原文 | 语义 |
|---|---|---|
| `bCompileResultValid && bCompiledClean` | `✓ M_xxx  已编译，0 错误 0 警告` | 真·编译通过 |
| `bCompileResultValid && !bCompiledClean` | `✗ M_xxx  已编译，N 错误` | 真·编译失败 |
| `!bCompileResultValid` | `— M_xxx  未执行编译（拿不到 MaterialResource，本行不代表编译结论）` | **不冒充结论** |

### 3.4 冷加载核对纳入 SamplerType

`VerifyImportedAssets()` 遍历材质采样节点时，对每个节点核一遍，失败时把期望
（含贴图名）与实际并排打出来：

```
✓ BaseColorTexture.SamplerType = Color
✓ NormalTexture.SamplerType = Normal
✓ ORMTexture.SamplerType = Masks
✓ HeightTexture.SamplerType = Linear Grayscale
```

### 3.5 负向回归测试 `-TestSamplerTypeCheck`

> **一个永远返回 true 的校验器，同样能让所有报告变绿。**

所以新增的校验必须有测试证明它在**错误输入下真的会失败**。用例 8 条，纯内存构造
（transient `UTexture2D`，不需要 ComfyUI、不需要已落盘资产）：

| 用例 | 期望 |
|---|---|
| height `TC_Grayscale` + `Grayscale` ← **M2 踩的坑** | 拒绝 |
| orm `TC_Masks` + `LinearColor` ← **M2 踩的坑** | 拒绝 |
| height `TC_Grayscale` + `LinearGrayscale` | 通过 |
| orm `TC_Masks` + `Masks` | 通过 |
| albedo `TC_Default` + `Color` | 通过 |
| normal `TC_Normalmap` + `Normal` | 通过 |
| 边界：`TC_Grayscale` + sRGB **开** + `Grayscale` | 通过 |
| 边界：`TC_Masks` + `Normal`（不是"任何非 Color 都放过"） | 拒绝 |

顺带修：`ComfyTextureStudioEditor.Build.cs` 补 `RHI` 依赖
（`GMaxRHIShaderPlatform` 的符号在 RHI 模块，`RenderCore` 里没有 —— 否则 LNK2019）。

## 5. 旧资产怎么办

`/Game/ComfyTextures/cts_m2_verify2/` 里的 `M_`/`MI_` 是**用旧代码建的，SamplerType 仍是错的**。
两种处理方式：

1. **推荐**：直接打开新导入的 `/Game/ComfyTextures/cts_samplerfix/M_cts_samplerfix` 验收 ——
   它是修正后的代码产出的，SamplerType 已正确。
2. 想留住 `cts_m2_verify2` 这个基名：删掉该文件夹下的 `M_`/`MI_` 两个资产，重跑一次 `-Import -BaseName=cts_m2_verify2`。

也可以手工改：打开材质 → 选中 `HeightTexture` 节点 → Details → `Sampler Type` 改
`Linear Grayscale`；`ORMTexture` 改 `Masks`。

## 6. 教训

1. **验收手段本身也要被验收。** `RecompileMaterial` 返回空数组这件事，
   看起来是"编译通过"，实际是"没编"。凡是把"没有错误"当作"通过"的地方，
   都要先问一句：**这个"没有错误"是怎么产生的？**
   —— 已加 `bCompileResultValid` 把两者分开，并在报告里显式写出"本行不代表结论"。

2. **规范错了，代码只会更忠实地错。** PRD §6.2 那张表是手写的，而它描述的规则
   引擎里本来就有现成实现。**能问引擎的就别手抄**：抄的那一刻就多了一份会过期的真相。
   —— 现在 `ComfySamplerType` 是纯转发，没有自己的映射表。

3. **没被定义的检查项一定会漏。** M2 的属性表自检和结构自检都是"按清单核"，
   清单里没有"节点 ↔ 贴图"这一层，于是它就成了盲区。
   —— 新增 `-TestSamplerTypeCheck` 的 8 条断言把这一格补上。

4. **负向测试是自检的必需品。** 正例全绿只能说明"没崩"，说明不了"查得出来"。
   —— 与 `-TestLiveness`（用栈上探针证明回调被挡住）是同一个套路。
